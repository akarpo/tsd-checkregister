# Working Folder

Source data and project documentation for the Check Register Reconciliation project. The user-facing artifacts (`index.html`, `Troy_SD_Check_Register_FY11-FY26.xlsx`, `Missing_Months_FY11-FY26.xlsx`) live at the **repo root**, not here.

## Fiscal year

One `Fiscal Year` column, derived from each line item's **issue date** on the
Michigan Jul 1 – Jun 30 boundary. `Source Meeting` is provenance only. The rule
and the source-date repairs live in `Cache and Tools/build/fiscal_year.py`; see
the root [`README.md`](../README.md#fiscal-year-attribution) for why the earlier
meeting-keyed column was retired (2026-07-27).

## Status

The original FY23-FY26 dashboard and workbook were built through the Claude.ai web interface; those prompts were not captured. The FY21-FY22 backfill (April 2026), FY12-FY19 backfill (May 2026), and the Mar-May 2026 ingest + single-fiscal-year refactor (July 2026) were done through Claude Code, which now provides a consolidated, portable build pipeline under `Cache and Tools/build/`. See the root [`README.md`](../README.md#reproducibility) for the stages, the `--assemble-only` path, and caveats.

**Nothing on the dashboard is hand-maintained.** Every figure is derived by the pipeline and carried in the page's data payload; the page renders from it. Editorial wording is authored — why a spike happened, which board action it maps to — but the numbers inside it interpolate. This was the last thing to change (July 2026): the curriculum spotlight used to run on hard-coded per-FY totals pasted in by hand, which let a swimlane filter bug go unnoticed for years. If you are tempted to fix a number by editing `index.html`, fix it in the pipeline instead.

## Checking the numbers

Three layered checks, all under `Cache and Tools/build/`:

| Script | Answers |
|---|---|
| `validate.py` | Do the artifacts agree with each other? |
| `check_source_fidelity.py` | Does the dataset match the source PDFs? |
| `check_published_figures.py` | Does every number on the page trace to the dataset? |

`validate.py` alone is not enough, and the layering is not academic: a parser that silently drops rows drops them from every artifact at once, so `validate.py` stays green. That is exactly what happened in July 2026 — it reported 6/6 while a regex cap was discarding 16-digit budget units. `check_source_fidelity.py` caught it by reconciling against the `TOTAL REPORT` figure each PDF prints about itself.

A prompt-history scaffold lives under `Prompts/` and at the root in [`PROMPTS.md`](../PROMPTS.md). Any future revision (FY refresh, dashboard change, pipeline work) should be run through Claude Code with the prompt logged in both places, so the project stays reproducible going forward. If the original Claude.ai conversations are recovered, backfill them into the same structure.

Note: most source PDFs are excluded from git (see the root README "Source PDFs" note); the workbook and dashboard are committed as complete, current artifacts.
